# スライド3　背景：AIエージェントとツール利用

## 画面に載せる内容

### 背景：LLMは外部ツールとの連携で実行能力を広げられる

AIエージェントは、LLMと外部ツールを組み合わせてタスクを実行する。

`質問 → 推論 → ツール実行 → 結果の確認 → 回答`

ツール利用が影響する要素

- 回答の正確性
- 処理コスト
- 応答時間

## 話す内容（約35秒）

LLMは文章生成だけでなく、計算機能や検索機能などの外部ツールと連携することで、より多様なタスクを処理できます。AIエージェントは、質問を読み、必要なツールを判断して実行し、その結果を使って回答します。そのため、ツール利用の良し悪しは、回答品質、コスト、応答時間に影響します。

# スライド8　アプローチ③：GEPAとDSPy Optimizer

## 画面に載せる内容

### アプローチ③：GEPAが失敗のフィードバックから指示を改善する

GEPAの流れ

`Agent実行 → 採点・feedback → 振り返り → 新しい指示 → 再評価`

今回GEPAを選んだ理由

- 数値スコアだけでなく、文章feedbackを利用できる
- ツールの実行履歴を基に失敗原因を振り返れる
- 改善したinstruction候補を比較できる

他のDSPy Optimizer

| Optimizer | 主な最適化対象 |
|---|---|
| BootstrapFewShot | few-shot例 |
| MIPROv2 | instructionとfew-shot例 |
| BootstrapFinetune | LMの重み |

## 話す内容（約50秒）

GEPAは、Agentの実行結果に対する数値スコアと文章のfeedbackを読み、失敗原因を振り返って新しいinstructionを提案するOptimizerです。今回は、ツールの選択や順序について具体的なfeedbackを与えられるためGEPAを選びました。DSPyには他にも、良い実行例をfew-shot例として追加するBootstrapFewShot、instructionと例を同時に探索するMIPROv2、モデルの重みを調整するBootstrapFinetuneなどがあります。

## 出典

- [DSPy公式：Optimizerの選び方](https://dspy.ai/diving-deeper/choosing-an-optimizer/)
- [DSPy公式：GEPA](https://dspy.ai/api/optimizers/GEPA/overview/)

# スライド9　評価方法：Judge LMによる重み付き評価

## 画面に載せる内容

### 評価方法：4項目をJudge LMで採点し、重み付きで統合した

| 評価項目 | 内容 | 重み |
|---|---|---:|
| Tool Selection | 適切なツールを選んだか | 0.40 |
| Tool Necessity | 必要・不要、重複呼び出しは妥当か | 0.20 |
| Arguments | 引数と実行順序は適切か | 0.15 |
| Task Success | 最終回答が要求を満たしたか | 0.25 |

1問のスコア

`0.40×選択 + 0.20×必要性 + 0.15×引数 + 0.25×達成度`

全体スコア

`各問題のスコアの平均 × 100`

## 話す内容（約55秒）

評価にはJudge LMを使用しました。各実行について、ツール選択、ツールの必要性、引数と順序、最終回答の4項目を0から1で採点します。今回の目的はツール選択の最適化なので、Tool Selectionを40パーセントと最も重くしました。1問の重み付きスコアを計算し、全問題の平均を100点換算した値をBaselineとGEPA後で比較します。また、GEPAには数値だけでなく、日本語の具体的なfeedbackも渡します。

## 発表用の計算例

`選択1.0、必要性0.8、引数0.6、達成度0.9 → 0.875 → 87.5点`
